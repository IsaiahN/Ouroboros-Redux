# PREREG — THE 30 GB HARD CEILING (2026-08-18, Seat 3's order)

AUTHORITY: Isaiah — *"Hard ceiling: 30 GB, cleanup kicks in. Set it now, optimize later."*
**AND THE REASON IT IS NOT PHASE TWO:** the ablations, the arms and the seed-stability runs
already on the board **each produce a box**. Retention is a **precondition** for those
experiments, not a tax on reaching them.

## THE THREE REQUIREMENTS, TAKEN AS BINDING

### 1 · IT GATES, IT DOES NOT WARN
Checked **BEFORE** a long run starts and **PERIODICALLY DURING**. On breach it **STOPS THE
RUN** and returns a non-zero exit. **A ceiling that logs is a ceiling that scrolls past**,
and this project has two rung-0e failures in one day from exactly that.

### 2 · THE ACTION IS SPECIFIED NOW — ARCHIVE-THEN-TRUNCATE, NEVER DELETE
**Under the evidence-preserving law and the ledger genus** (*a fix that destroys the record
of the thing it fixed*): rows move to a compressed archive, the live stream is truncated,
**and nothing is destroyed.** A truncation that cannot be undone is a deletion wearing
another name.

**AND "SUPPORTS A LIVE CLAIM" IS SETTLED HERE, BECAUSE IF IT IS NOT THE CEILING FIRES INTO
NOTHING.** A path is CLAIM-SUPPORTING, and is kept **REGARDLESS OF AGE OR SIZE**, if ANY of:
  **(a) IT HAS A LIVE READER** — it is NOT on `tools/consumption_sweep.py`'s unpaired list.
      A stream something reads is load-bearing by definition.
  **(b) IT IS CITED BY A LIVE CLAIM DOCUMENT** — named in `CLAIM.md`, `UNDERPOWERED.md`,
      `LINK3_AUDIT.md`, `BOARD_AUDIT.md`, or any `PREREG_*.md` whose experiment has not
      reported. **The under-powered register makes this concrete: every re-run pending
      needs its baseline population intact.**
  **(c) IT IS IRREPLACEABLE** — it cannot be regenerated by re-running. **`levelup_frames`
      is the worked case: 9 records, the ONLY genuine frame corpus this project has, and
      the whole link-3 finding rests on them.**
  **(d) IT IS A CONTROL** — anything under `.runs/arms/`, ever. A measurement's own box is
      never a cleanup target.

**EXPLICIT KEEP-ALWAYS LIST** (the beat rule, made mechanical): **fabrics, logs, controls,
`levelup_frames`, `winning_sequences`, every `delta_*.json`.**
**ELIGIBLE FOR ARCHIVE-THEN-TRUNCATE:** the high-churn streams whose *consumers read only a
tail* — `settlements`, `import_queue`, `mint_verdicts`, and the `action_traces` table.
**AND EVEN THESE ARE ARCHIVED, NOT DROPPED**, because rung 3 reads settlement HISTORY and
the janitor's own trap was that folding to a tail would delete it.

### 3 · THE WAL IS IN THE BUDGET
**Counted: `*.db` + `*.db-wal` + `*.db-shm` + every fabric stream + logs.** 30 GB of DB
with a 20 GB WAL beside it is 50 GB on disk, and the durability test just measured WAL
sizes varying **5.4x** with one pragma.

## THE NUMBER
**`DISK_CEILING_GB = 30`**, overridable by env `DISK_CEILING_GB`.
**SEAT 3'S NOTE CARRIED: 30 GB MAY ALREADY EXCEED KAGGLE'S WORKING-DIRECTORY QUOTA**
(~20 GB, and it drifts). **THE NUMBER COMES DOWN LATER; THE MECHANISM DOES NOT WAIT.**
A second env `DISK_WARN_FRACTION` (default 0.8) triggers the archive sweep *before* the hard
stop, so the ceiling is reached only if archiving cannot keep up.

## FALSIFIERS
**F1 · IT STOPS A RUN.** With the ceiling set below current usage, a guarded run **exits
non-zero and does not proceed**. *Fails if:* it logs and continues.
**F2 · IT NEVER DESTROYS.** After an archive-then-truncate, **every archived record is
recoverable byte-identically** from the archive. Asserted by round-trip, not by inspection.
**F3 · IT NEVER TOUCHES CLAIM-SUPPORTING DATA.** With `levelup_frames`, an arm box and a
cited stream present, a forced sweep leaves all three **byte-identical**. *Fails if:* any
keep-always path changes by one byte.
**F4 · THE WAL COUNTS.** A DB with a large WAL reports usage including it.

## UNDO
The archive is a directory. **Restoring is concatenating the archive back onto the live
stream** — no schema change, no state migration. The ceiling itself is one env var.
