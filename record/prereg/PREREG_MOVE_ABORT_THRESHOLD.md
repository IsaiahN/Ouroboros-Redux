## THE QUESTION THIS ANSWERS
"Would it be easier to start from scratch and import what you need?" Answered NO, on three
grounds recorded in BEAT 57: (a) the import list IS the subtraction's output, so scratch
cannot be reached more cheaply than through the move; (b) the move is falsifiable slice by
slice and a rewrite is unfalsifiable by construction (FIGURE 10); (c) the asset in this tree
is the FOUND DEFECTS, which are invisible to a green suite and would be silently
reintroduced by a fresh tree.

## THE THRESHOLD — MEASURED PER SLICE, NOT ARGUED
**A slice that must EDIT more live modules than it MOVES is a rewrite wearing a move's
clothes.** On any slice where edited > moved, the move HALTS and the arithmetic goes to the
GM before another slice is cut. This is a stop rule, not a warning.

## THE SECOND STOP RULE, ALREADY IN THE SLICE-1 BRIEF
The ladder slice predicts the loop's action sequence on a constructed board is IDENTICAL
with and without the ladder. **If the sequences differ, nothing moves and the ruling
reverts.** That outcome is a SUCCESS OF THE METHOD, not a failure of the build, and it will
be reported as one.

A green suite. 2038 passing sees neither string-loaded modules nor lazy imports, both of
which failed as WARNINGS twice in this examination. **The fleet run is the test after each
slice.** A pytest exit code is not a slice's gate and never was.
